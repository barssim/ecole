

# POLITIQUE DE SÉCURITÉ DES INFORMATIONS

**Version : 1.0**

## 1. Objectif

Cette politique définit les mesures minimales destinées à protéger les informations traitées par [NOM].

## 2. Contrôle des accès

Les accès sont attribués selon le principe du moindre privilège.

Exemple de rôles :

* Super Administrateur ;
* Directeur ;
* Administration ;
* Enseignant ;
* Comptabilité ;
* Parent ;
* Élève.

Chaque rôle dispose uniquement des permissions nécessaires.

## 3. Authentification

Les utilisateurs doivent utiliser des identifiants individuels.

Les comptes administrateurs doivent bénéficier, lorsque techniquement disponible, d'une authentification renforcée.

Les mots de passe doivent être stockés sous une forme protégée et non en clair.

## 4. Chiffrement

Les communications avec la plateforme doivent être protégées par HTTPS/TLS.

Les données sensibles stockées doivent bénéficier de mesures de protection adaptées au niveau de risque.

## 5. Sauvegardes

Des sauvegardes sont effectuées selon une fréquence définie par l'équipe technique.

Configuration cible :

* sauvegarde quotidienne ;
* conservation [7/30/90] jours ;
* test périodique de restauration ;
* accès aux sauvegardes limité.

## 6. Journalisation

Les événements de sécurité importants peuvent être journalisés, notamment :

* connexions ;
* échecs de connexion ;
* modifications de permissions ;
* opérations administratives ;
* suppression de données ;
* événements de sécurité.

## 7. Gestion des incidents

Tout incident suspecté doit être enregistré.

Processus :

**Détection → Qualification → Containment → Correction → Récupération → Documentation**

Les incidents susceptibles d'affecter des données personnelles sont traités conformément au DPA.

## 8. Développement sécurisé

Les nouvelles fonctionnalités doivent être vérifiées avant leur mise en production.

Les vulnérabilités critiques doivent être corrigées dans un délai approprié au risque.

## 9. Accès aux données par l'équipe technique

Les accès techniques aux données doivent être :

* nécessaires ;
* limités ;
* autorisés ;
* traçables lorsque techniquement possible.

## 10. Prestataires

Les fournisseurs d'hébergement, sauvegarde, messagerie, SMS ou autres services critiques doivent être évalués selon leur importance et leur accès potentiel aux données.

## 11. Continuité

Le Prestataire maintient des mécanismes raisonnables de restauration du service après incident.

## 12. Révision

La présente politique est révisée au moins une fois par an ou après un incident majeur.
